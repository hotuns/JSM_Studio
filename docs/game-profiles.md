# 游戏配置与动作映射

在侧栏选择「游戏配置」，点击「添加游戏」。填写要配置的游戏名称，选择使用基础动作或从空白列表开始。

## 向导

1. **填写游戏与输入方式**：游戏名初始为空，由用户填写；配置名称可选，留空时自动使用游戏名。不支持手柄或混合输入不顺畅的游戏选择「完整键鼠映射」。支持混合输入的游戏可以选择「原生手柄 + 体感鼠标」。
2. **核对动作**：逐项对照游戏内的键鼠键位。列表中的键鼠键位和手柄操作可以直接点击录入，不必打开弹窗；按 Esc 或取消录入退出。动作列表不按分类分组，支持搜索和「添加动作」。最后一列为「操作」，提供「设置 / 删除」；设置时可修改动作名称、键鼠输出、手柄输入以及按下、长按或组合键。删除前在行内确认，可删除全部动作后重新添加。支持键鼠录入和手柄实时录入，包括模拟扳机、左摇杆方向和扩展按键。录入使用选中的设备。
3. **设置体感**：选择轴向、按住瞄准键启用或始终启用，以及初始灵敏度。已在当前用户设备上验证的飞智方案为横向 X / 纵向 Z；其他设备默认横向 Y / 纵向 X。轴向方案需要自行验证，不代表对所有飞智设备和连接模式都适用。
4. **检查并创建**：查看输入屏蔽说明，默认只保存独立配置到配置库，保留当前选择和正在运行的映射；只有勾选「保存后立即应用到映射引擎」才会切换。保存后可在配置库点击「加载并应用」。已有同名配置会由底层生成唯一文件名，不覆盖原文件。

完整键鼠模板让左摇杆输出 WASD，右摇杆与体感输出鼠标。初始安排包括 LT 瞄准、RT 开火、A 跳跃、B 蹲伏 / 长按卧倒、X 换弹 / 长按交互、Y 切换武器等。

基础布局是建议起点，适用于创建不同游戏的配置，**不代表特定游戏的官方默认布局**。所有动作初始标为「待核对」。游戏模式、干员、版本、用户修改，以及游戏的情境判定都可能影响实际操作。载具和复杂轮盘暂不包含在首版模板中。

## 高级配置与保存

- 动作表编辑后显示「有未保存的修改」。「保存配置」或 Ctrl+S 只更新文件，不调用引擎应用接口；「应用修改」或 Ctrl+Enter 保存并切换引擎设置。已保存但尚未应用时会单独提示。继续编辑后撤销，会回到最近保存的内容。导出独立生成分享 TXT，不改变配置文件或引擎。
- 游戏名称与输入方式保存在 `# JSM_STUDIO_GAME ` 开头的明文 JSON 注释中；动作列表使用 `# JSM_STUDIO_ACTION ` 注释，每个动作一行。中文名称可直接阅读，不再使用 URI 编码。JSM 引擎忽略这些注释。
- 游戏名独立于文件名，向导可以填写游戏名。分享后，即使别人重命名 TXT，仍能恢复正确的游戏名、动作名称、按键、触发方式和核对状态。
- 点击游戏配置页的「导出 TXT」即可导出当前编辑内容，包括未应用的修改、动作注释和完整 JSM 命令。导出不改变正在运行的映射。
- 接收者通过「导入 / 配置库」导入 TXT。有效 Studio 游戏配置会保留完整 JSM 设置，正常保存、复制和配置标准化也会保留动作注释。旧版单行编码注释仍可读取，导出时转换为明文格式。
- 不依赖本机的模板文件或单独 JSON 数据库。也支持 `template: "custom"` 的自定义游戏及动作列表；请保留每条动作中的唯一 id、名称、分组、键位等字段。
- 「高级按键映射」「体感与视角」「配置源码」继续可用。
- 动作编辑只修改发生变化的按键分配，保留其他高级命令。迁移瞄准按键时，如果 `GYRO_ON` 仍指向原瞄准键，会随之迁移。
- 高级编辑导致受管按键与动作表不一致，或出现重复赋值时，暂停动作编辑并显示差异。用户可继续使用高级配置，或明确选择以动作表恢复受管键位；其他命令保留。
- 原有配置不会被自动转换或覆盖。没有动作资料的配置继续通过高级界面编辑。

## 游戏内验证

完整键鼠模式需要避免游戏同时接收物理手柄输入。软件仅提供 HidHide 官方下载与设置入口，不自动安装、配置或宣称屏蔽成功。请允许实际运行并读取手柄的 JoyShockMapper.exe 访问隐藏设备，然后在游戏内自行验证。

建议在训练场依次测试移动、右摇杆 / 体感视角、瞄准与开火、换弹 / 交互、菜单与背包。瞄准建议设为按住；冲刺、蹲伏的按住 / 切换行为应与所配置的键盘动作匹配。共享轻按 / 长按按键时，轻按可能在释放时才触发。

## 开发验证

在 `JSM_GUI/jsm_gui_tauri` 运行：

```powershell
npm run test:games
npm run build:web
```

自动检查覆盖命令生成、资料导入与标准化、轻按 / 长按与组合键、冲突拒绝、按键迁移、体感启用键联动和高级设置保留。自动测试不能代替真实游戏手感和屏蔽结果的验证。

## 单文件分享格式（v2）

文件由两部分组成：前面的结构化注释供 Studio 恢复界面，后面的普通命令供 JSM 执行。两部分一起分享。

```text
# JSM_STUDIO_GAME {"version":2,"gameName":"我的游戏","template":"custom","mode":"keyboardMouse"}
# JSM_STUDIO_ACTION {"id":"jump","zh":"跳跃","en":"Jump","group":"move","key":"SPACE","button":"S","gesture":"press","modifier":"","confirmed":true}

RESET_MAPPINGS
AUTOCONNECT = ON
TELEMETRY_ENABLED = ON
TELEMETRY_PORT = 8974
GYRO_OUTPUT = MOUSE
GYRO_SENS = 1 1
S = SPACE
```

`button` 使用 JSM 按键名，例如 S 对应 A、W 对应 X、ZL 对应 LT。`gesture` 支持 `press`、`hold`、`chord`；组合键的修饰键放在 `modifier`。动作分组为 `move`、`combat`、`equipment` 或 `menu`。

手工只改注释不会自动改动下面的实际 JSM 命令。两者不一致时，Studio 会显示受管按键差异，避免在读取文件时静默覆盖高级映射。可以在界面编辑动作同步生成命令，或明确选择恢复动作表布局。

完整示例见 `docs/examples/delta-force-infantry.txt`，它是需要游戏内核对的建议布局。
